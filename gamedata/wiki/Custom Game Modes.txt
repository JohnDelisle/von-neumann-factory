= Custom Game Modes =
== Overview ==

The game allows to import custom scenarios and custom scenario presets as [https://www.json.org/ json] files. These files are packaged inside a [[Modding | Mod]], which provides an easy way to add custom scenarios along with the mod's other features. Importantly, the game automatically loads the custom content if it's in the correct place, meaning that you can make and distribute custom scenarios without coding anything in C#, which is referred to as a "non-code mod". These non-code mods are sometimes not considered real mods, since they can only modify features the game allows to modify, and also because historically (before the 1.0 update), custom scenarios used to be loadable without mods via dedicated folders. They are however still mods, meaning that creating and publishing custom scenarios still follows some of the workflow for creating code mods, like making a folder in the [[Game Files#mods | mods]] folder, or making a [[Mod Development#Mod Manifest | manifest.json]] file. See [[Modding]] for full details.

You can open json files like regular text files, although using a specialized editor that supports editing json is recommended.

The ingame scenarios can be used as a base to create custom scenarios. To access them, use the [[Debug Console#debug.export-game-data | debug.export-game-data]] [[Debug Console | console command]], then in the [[Game Files#Persistent Data Folder | Persistent Data Folder]], open the [[Game Files#basedata-vXXXX | basedata]] folder. In there, the [[Game Files#scenarios | scenarios]] and [[Game Files#scenario-parameter-presets | scenario-parameter-presets]] folders will contain the ingame content. Keep in mind that the ingame scenarios can't be loaded directly without modifications, see the section below for more details.

If you're having issues loading a custom scenario, here is a quick checklist of common mistakes. Refer to the full documentation below this section to get more details on specific points.

* Make sure you have a [[Mod Development#Mod Manifest | manifest.json]] file.
* Make sure you have a [[#Custom Scenario Presets | Custom Scenario Preset]] pointing to your custom scenario.
* Make sure there is a space between <code>"FormatVersion":</code> and <code>3,</code>.
* Make sure the <code>UniqueId</code> keys for the scenario and the scenario preset are different from the ingame IDs.
* Make sure the <code>ToolbarConfig</code> value is an [[#Include Raw | Include Raw]] string.

== Include Syntax ==

Custom scenarios and scenario presets support a special include syntax which allows including content from resource files to reduce repetitions across scenarios. The syntax to use is <code>"#include:<path>"</code> (including the <code>"</code>s), with <code><path></code> the path to the resource file without the file extension (and without <code><</code> or <code>></code>).

The path is passed to the [https://docs.unity3d.com/ScriptReference/Resources.Load.html Resources.Load] Unity method, meaning that it can be used to include the content from any file in a <code>Resources</code> folder inside the game files. The ingame files inside <code>Resources</code> folders that are not made for scenarios will result in invalid scenario files if used with the include syntax, meaning that this syntax is only useful if the path points to a scenario component file, i.e. the path starts with <code>Scenarios/</code>. You can find a list of all ingame scenario components in [https://github.com/Loupau38/shapez2-assets/tree/main/assets/scenarioComponents this link]. The include syntax can't load mod provided files without a mod that adds that functionality with code.

The include strings are processed before the json object is parsed, meaning that they can be anywhere in the file, even in places that make the file not valid json, as long as it results in valid json after the include strings are processed. When an include string is processed, the content of the file associated to the path is gathered, then any include strings inside the content get processed, and finally the resolved content fully replaces the string in its place.

=== Include Raw ===

The game has an alternative "include raw" syntax, similar to the include syntax, but with notable differences:

* The prefix is <code>#include_raw:</code>.
* It's not processed before the json is parsed.
* It can only be used as a string value for an object key that expects an include raw string.
* Unlike the regular include, it's not optional, if an object key expects an include raw string, it can't be the value that will replace the string.
* Include strings or raw include strings contained inside the associated file content are not processed immediately<ref name="no-immediate-parse">Though include string and json parsing can be done at a later stage ingame.</ref>.
* The string is converted to a custom C# object containing the file content as a string (json parsing is not done immediately<ref name="no-immediate-parse"/>).

== Custom Scenarios ==

Custom scenario files must be placed in the <code>scenarios</code> folder inside the root folder of the mod that wants to load the custom scenarios.

{{JSON-Format-Description}}

=== Main Object Format ===

* <code>FormatVersion</code> number: The format version of the file, currently <code>3</code>. The game checks this value in the raw file content, meaning that the file must contain the exact string <code>"FormatVersion": 3,</code> (i.e. with a space after the <code>:</code>) anywhere in the file, but the value is otherwise unused.
* <code>GameVersion</code> number: Supposedly the game version number this scenario was made for, but the value doesn't have any impact.
* <code>UniqueId</code> string: The ID used by the game to identify the scenario, so it has to be unique. It also means the scenario file name doesn't matter.
* <code>IsTutorial</code> bool: Indicates if the scenario is a tutorial scenario, mostly for main menu UIs.
<!---->
* <code>SupportedGameModes</code> array (default: <code>[]</code>): An array of strings indicating the game modes supported by this scenario. The full list is used to determine under which game mode(s) the scenario will be shown in the scenario selection screen. Only the first value in the list is used to determine the actual game mode that will be used when playing the save. The vanilla game mode IDs are <code>RegularGameMode</code>, <code>ConverterGameMode</code>, and <code>TutorialGameMode</code>.
* <code>NextScenarios</code> array (default: <code>[]</code>): An array of strings of scenario IDs that can be selected after completing the current scenario. The scenario selection screen will only be shown if the <code>IsTutorial</code> key is <code>true</code>. If the scenario is a tutorial, providing an empty array will softlock the game when the selection screen shows up.
* <code>ExampleShapes</code> array (default: <code>[]</code>): An array of strings of shape codes<ref name="shape-code"/>. Only the first value is used for the shape on the scenario badge, and thus on the scenario selection screens. If the array is empty then the badge won't have a shape.
<!---->
* <code>Title</code> TranslationString: The scenario's title.
* <code>Description</code> TranslationString: The scenario's description.
* <code>PreviewImageId</code> string: The ID of the image that will show in the background in the scenario selection screens.

** <code>MaxShapeLayers</code> number (default: <code>4</code>): The maximum number of layers that shapes can have.
** <code>InitialResearchPoints</code> number: The number of research points given when starting a save with the scenario. Will be added to any research points rewards given by initially unlocked milestones and jobs.
** <code>ShapesConfigurationId</code> string: Which types of shapes the scenario uses. Any other value gives the same result as <code>0</code>.

** <code>TutorialConfig</code> string: What tutorial to use. The vanilla tutorial config IDs are <code>TCOnboarding</code> for the classic mode tutorial, <code>TCConverter</code> for the manufacture mode tutorial, and <code>TCNoTutorial</code> for no tutorial.

=== Rewards Object Format ===

* <code>$type</code> string: The type of reward, can be <code>BlueprintCurrencyReward</code>, <code>ResearchPointsReward</code>, <code>ChunkLimitReward</code>, <code>BuildingReward</code>, <code>IslandGroupReward</code>, <code>ContentBundleReward</code>, or <code>MechanicReward</code>.
* <code>Amount</code> number: The amount if it's a blueprint points, research credits<ref name="research-point"/>, or platform capacity<ref name="chunk-limit"/> reward.
* <code>BuildingDefinitionGroupId</code> string?: The machine variant ID if it's a machine reward.
* <code>GroupId</code> string?: The platform group ID if it's a platform group reward.
* <code>ContentBundleId</code> string?: The content bundle ID if it's a content bundle reward.
* <code>MechanicId</code> string?: The mechanic ID if it's a mechanic reward.

=== Costs Object Format ===

* <code>$type</code> string: The type of cost, can be <code>ResearchPointsCost</code> or <code>FixedShapeCost</code>.
* <code>Amount</code> number: The amount of research credits<ref name="research-point"/> or shapes required.
* <code>Shape</code> string: The shape code<ref name="shape-code"/> if it's a shape cost.

=== Position Transform Object Format ===

Represents a space level position relative to an origin point.

* <code>X</code> number: The X offset.
* <code>Y</code> number: The Y offset.
* <code>Z</code> number: The Z offset.
* <code>Rotation</code> number: The rotation.

=== Notes ===

<ref name="upgrade">In this context, the term "upgrade" refers to a milestone, job, or shop item, except for linear upgrades.</ref>
<ref name="shape-code">Any shape code must be valid under the [[Shapes#Strict Ruleset | Strict Shapes Ruleset]].</ref>
<ref name="chunk-limit">Any platform capacity value will be halved when displayed ingame. This is to keep integer values while allowing platforms like space belts to have a cost of 0.5.</ref>

== Custom Scenario Presets ==

Custom scenario preset files must be placed in the <code>scenario-presets</code> folder inside the root folder of the mod that wants to load the custom scenario presets. Although scenario presets are no longer displayed ingame, a scenario preset pointing to a specific scenario is still required to start a save with said scenario. The scenario presets exported by the game using the [[Debug Console#debug.export-game-data | debug.export-game-data]] command are the raw files, meaning that the [[#Include Syntax | Include Strings]] are not resolved. You can find the complete versions in [https://github.com/Loupau38/shapez2-assets/tree/main/assets/scenarioParameterPresets this link].

{{JSON-Format-Description}}

=== Main Object Format ===

* <code>Version</code> number: No effect. The game also accepts the value as a string (which is the case in the ingame scenario presets) due to the JSON loader used being permissive, but the string must still represent a valid integer.
* <code>UniqueId</code> string: The ID used by the game to identify the scenario preset, so it has to be unique, it also means the scenario preset file name doesn't matter.
* <code>Title</code> TranslationString: The scenario preset's title.
* <code>Description</code> TranslationString: The scenario preset's description.
* <code>Parameters</code> object: The actual data of the scenario preset, it has the following keys:
** <code>MapGenerationParameters</code> object: The configuration of the map generation settings, it has the following keys:
<!---->
*** <code>FluidsSpawnPrimaryColors</code> bool (default: <code>true</code>): Whether or not to spawn fluid patches of the primary colors.
*** <code>FluidsSpawnSecondaryColors</code> bool: Whether or not to spawn fluid patches of the secondary colors.
*** <code>FluidsSpawnTertiaryColors</code> bool: Whether or not to spawn fluid patches of the tertiary colors.
<!---->
*** <code>FluidPatchLikelinessPercent</code> number (default: <code>15</code>): The likeliness of fluid patches as a percentage.
*** <code>FluidPatchBaseSize</code> number (default: <code>2</code>): The base size of fluid patches.
*** <code>FluidPatchSizeGrowPercentPerChunk</code> number (default: <code>70</code>): How much fluid patches should grow per chunk as a percentage.
*** <code>FluidPatchMaxSize</code> number (default: <code>4</code>): The maximum size of fluid patches.
<!---->
*** <code>ShapePatchLikelinessPercent</code> number (default: <code>30</code>): The likeliness of shape patches as a percentage.
*** <code>ShapePatchBaseSize</code> number (default: <code>2</code>): The base size of shape patches.
*** <code>ShapePatchSizeGrowPercentPerChunk</code> number (default: <code>70</code>): How much shape patches should grow per chunk as a percentage.
*** <code>ShapePatchMaxSize</code> number (default: <code>5</code>): The maximum size of shape patches.
<!---->
*** <code>ShapePatchShapeColorfulnessPercent</code> number (default: <code>50</code>): The colorfulness of shape patches as a percentage.
*** <code>ShapePatchRareShapeLikelinessPercent</code> number (default: <code>30</code>): The likeliness of rare shapes in shape patches as a percentage.
*** <code>ShapePatchVeryRareShapeLikelinessPercent</code> number (default: <code>10</code>): The likeliness of very rare shapes in shape patches as a percentage.
<!---->
*** <code>SpiralGeneration</code> bool: Whether or not to use spiral-based generation for the map.
*** <code>SpiralThickness</code> number (default: <code>1.0</code>): The thickness of the spiral.
*** <code>SpiralTwist</code> number (default: <code>1.0</code>): The twist of the spiral.
<!---->
*** <code>ShapePatchGenerationLikeliness</code> array (default: <code>[{"GenerationType":"UncoloredFullShape","Weight":100}]</code>): An array of generation settings for each type of shape patch. There can be multiple elements with the same <code>GenerationType</code> value. Each element is an object with the following keys:
**** <code>GenerationType</code> string: The type of generation this object affects. Must be <code>UncoloredHalfShape</code>, <code>UncoloredAlmostFullShape</code>, <code>UncoloredFullShape</code>, <code>UncoloredFullShapePure</code>, <code>PrimaryColorHalfShape</code>, <code>PrimaryColorAlmostFullShape</code>, <code>PrimaryColorFullShape</code>, <code>PrimaryColorFullShapePure</code>, <code>SecondaryColorHalfShape</code>, <code>SecondaryColorAlmostFullShape</code>, <code>SecondaryColorFullShape</code>, <code>SecondaryColorFullShapePure</code>, <code>TertiaryColorHalfShape</code>, <code>TertiaryColorAlmostFullShape</code>, <code>TertiaryColorFullShape</code>, or <code>TertiaryColorFullShapePure</code>.
**** <code>MinimumDistanceToOrigin</code> number: The minimum distance from the center of the map for this type of shape patch to generate. Must be between <code>0</code> and <code>50</code>.
**** <code>Weight</code> number: The relative weight (likeliness) of this type of shape patch. Must be between <code>0</code> and <code>100000</code>.
**** <code>MaximumDistanceToOrigin</code> number (default: <code>-1</code>): The maximum distance to the center of the map for this type of shape patch to generate. A negative value means no maximum distance. Must be <code>50</code> or less.
<!---->
** <code>GameRuleParameters</code> object: The configuration of the game rules, it has the following keys:
*** <code>RuleIds</code> array (default: <code>[]</code>): An array of strings of game rule IDs that should be enabled. Each one must be an existing game rule ID.
** <code>ScenarioId</code> string (default: <code>"default-scenario"</code>): The ID of the scenario this scenario preset should use.

== Difficulty Presets ==

The game currently doesn't support loading custom difficulty presets as json files, however you can still find the in-game ones in the [[Game Files#difficulty-presets | difficulty-presets]] folder of the [[Game Files#basedata-vXXXX | basedata]] folder.

{{JSON-Format-Description}}

=== Main Object Format ===

* <code>Version</code> number: No effect. The game also accepts the value as a string (which is the case in the ingame difficulty presets) due to the JSON loader used being permissive, but the string must still represent a valid integer.
* <code>UniqueId</code> string: The ID used by the game to indentify the difficulty preset.
* <code>Title</code> TranslationString: The difficulty preset's title.
* <code>IconId</code> string: The difficulty preset's icon ID.
* <code>Parameters</code> object: The actual data of the difficulty preset, it has the following keys:
** <code>ResearchShapeCostMultiplier</code> number (default: <code>100</code>): The Goal Multiplier as a percentage.
** <code>ChunkLimitMultiplier</code> number (default: <code>100</code>): The Platform Capacity multiplier as a percentage.
** <code>BlueprintCostMultiplier</code> number (default: <code>100</code>): The Copy/Paste Cost multiplier as a percentage.
